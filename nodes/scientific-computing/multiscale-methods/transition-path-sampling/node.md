Transition path sampling (TPS) samples the rare trajectories that take a system from one stable state $A$ to another state $B$, without knowing the mechanism or a reaction coordinate in advance. A path is a trajectory of $N$ time steps. The transition path ensemble weights each path by its probability under the dynamics, restricted to paths that start in $A$ and end in $B$. TPS samples this ensemble with a Metropolis Monte Carlo chain whose states are whole paths. The main move, *shooting*, takes a point of the current path and grows a new piece of trajectory from it with the true dynamics; the *shifting* move translates the path in time. For stochastic dynamics with these moves, a trial path is accepted exactly when it connects $A$ to $B$.

## In plain words

Picture a mountain range between two valleys. A walker in a fog takes random steps and almost never crosses. Searching for crossings by trying many walks from the first valley wastes almost all the effort.

TPS starts from one crossing, however crude. It picks a point on it and lets a new walk grow from that point, forward or backward in time. If the new walk still links the two valleys, keep it; if not, keep the old one. Repeat. Each new crossing differs a bit from the last, so the collection wanders through all the ways of crossing, and each way shows up as often as the true walker would use it.

## The problem

The input is a dynamics given as a time step (and its time reverse), the indicator functions of two stable states $A$ and $B$, a path length $N$, and one initial path from $A$ to $B$, which need not be typical. The output is a sequence of paths whose distribution tends to the transition path ensemble
$$\mathcal{P}_{AB}[x] \propto h_A(x_0)\, \pi(x_0) \prod_{i=0}^{N-1} p(x_i, x_{i+1})\, h_B(x_N),$$
where $\pi$ is the equilibrium distribution and $p$ the transition probability. Averages over these paths describe the mechanism, and the rate constant follows from a related ensemble (see Variants).

## The algorithm

```pseudo id=main
TPS(x[0..N], step, back, A, B, M)
L1  repeat M times
L2      choose shooting or shifting, each with probability 1/2
L3      shooting: pick k uniform in 0..N; with probability 1/2 regrow x[k+1..N] forward from x[k] with step, else regrow x[0..k-1] backward from x[k] with back
L4      shifting: pick s uniform in 1..s_max; with probability 1/2 drop x[0..s-1] and grow s steps at the end with step, else drop the last s points and grow s steps before x[0] with back
L5      if the trial path starts in A and ends in B, accept it; else keep x
L6      record x (also after a rejection)
L7  return the recorded paths
```

The function `back` is one step of the time reversed chain, $\tilde p(y, x) = \pi(x) p(x, y) / \pi(y)$; for a reversible dynamics, such as [Metropolis](/metropolis-hastings/) Monte Carlo or overdamped Langevin dynamics, it is the same as `step`. Because each new piece is generated by the dynamics itself, its probability in the path weight cancels the probability of generating it, and the Metropolis ratio reduces to the indicator of line L5. This is the one-way shooting move. For deterministic dynamics, such as Newtonian molecular dynamics, shooting changes the momenta at the slice slightly and integrates both ways; the acceptance then has an extra factor from the change of the equilibrium weight of the shooting point. Line L6 counts a rejected move as a new copy of the old path, which the Metropolis rule needs.

## Example

Take a Metropolis random walk on the states $0, 1, 2, 3, 4$ with the energies $0, 2, 3, 2, 0$ at $\beta = 1$: from state $i$ propose $i \pm 1$ with probability 1/2 each, reject a move off the ends, and accept a move with the probability $\min(1, e^{-\Delta E})$. Let $A = \{0\}$, $B = \{4\}$ and $N = 8$. A path from 0 reaches 4 at step 8 with probability $0.02626$, and the exact ensemble follows from matrix powers: $P(x_k = j) = p^k(0, j)\, p^{N-k}(j, 4) / p^N(0, 4)$. At the middle slice $k = 4$ this is $(0.1033, 0.2667, 0.2601, 0.2667, 0.1033)$, and the mean first time at which the path enters $B$ is $6.4283$.

Start from the crude path $0, 1, 2, 3, 4, 4, 4, 4, 4$, which crosses at once. With $s_{\max} = 2$, 20000 moves from `random.Random(0)` gave an acceptance of 0.488 and used 54548 steps of the walk. The measured slice $k = 4$ was $(0.107, 0.263, 0.250, 0.274, 0.106)$, and the mean entry time 6.432. The crude start, with entry time 4, is forgotten: typical paths wait in $A$ and cross late. Runs of 2000 moves with seeds 0 to 5 gave entry times between 6.21 and 6.59, which shows the size of the Monte Carlo error at that length.

In this small example the crossing is not rare, and simple sampling (run the walk from 0 and keep the paths that end in 4) needs only about 38 runs per reactive path. TPS pays off when the probability of a crossing within $N$ steps is so small that simple sampling never finds one.

## Correctness

The proof is in the correctness proof of this page. The path weight factors at any slice $k$ into a part before $k$, which by stationarity equals $\pi(x_k)$ times the probability of generating it backward from $x_k$, and a part after $k$, which is the probability of generating it forward. A shooting move replaces one of the two parts by a freshly generated one, so the path weight times the generation probability is symmetric between the old and the new path. A shift by $s$ is reversed by a shift by $s$ in the other direction, with the same cancellation. So every move satisfies detailed balance with respect to $\mathcal{P}_{AB}$, with the acceptance $h_A(y_0) h_B(y_N)$. Invariance gives the correct ensemble if the path chain is also irreducible, which holds for the example and is an assumption in general.

## Complexity

Each move generates on average about $N/2$ steps for a shot and $s$ steps for a shift, so $M$ moves cost $O(M N G)$ in the [real RAM](/real-ram/) model, with $O(N d)$ memory for the path. The number of moves needed for a given accuracy depends on how fast the path chain decorrelates; it is measured, not proved. Shots from slices near the middle of the transition are accepted most often and change the path most; shots from slices deep in $A$ or $B$ are almost always accepted but change little.

## Properties

- **No reaction coordinate.** The states $A$ and $B$ must be defined, but the path between them is not.
- **True dynamics.** Every accepted path is a trajectory of the dynamics, so the ensemble contains the real mechanisms, with their real weights.
- **Markov chain in path space.** Successive paths are correlated, and the results are averages with Monte Carlo errors.
- **Fixed length.** The basic ensemble has a fixed path length $N$; it must be longer than the time of a crossing but short compared with the waiting time in $A$.

## Variants and improvements

- **Rate constants.** The time correlation $C(t) = \langle h_A(x_0) h_B(x_t) \rangle / \langle h_A \rangle$ grows linearly, $C(t) \approx k_{AB} t$, for times between the crossing time and the waiting time. TPS computes $C(t)$ with umbrella sampling in path space, and $k_{AB}$ follows from its slope.
- **Two-way shooting.** For deterministic dynamics, perturb the momenta at the slice and integrate both ways; this is the standard move for molecular dynamics.
- **Flexible length and transition interface sampling.** Paths stop when they reach $A$ or $B$, which avoids waiting in the states; interfaces between $A$ and $B$ give the rate as a product of crossing probabilities, as in [forward flux sampling](/forward-flux-sampling/).
- **Committor analysis.** From points on the sampled paths, fire many short runs and measure the probability of reaching $B$ first; the points with probability 1/2 form the transition state ensemble, which tests a guessed [collective variable](/collective-variable/).

## When to use it

Use TPS for a rare transition between two well defined states when the mechanism is unknown, the dynamics matters, and a single crossing can be found, for example for nucleation, folding of small proteins, and chemical reactions in solution. Use the [string method](/string-method/) or the [nudged elastic band](/nudged-elastic-band/) when a minimum energy path is enough, and [forward flux sampling](/forward-flux-sampling/) when the dynamics is not reversible or the time reverse is not available.

## Pitfalls

- **A bad definition of the states.** If $A$ or $B$ includes points from which the system often returns, the ensemble contains paths that are not transitions. Both states must be small enough to exclude the transition region and large enough to be visited often.
- **A path that is too short.** Paths of length below the crossing time are rare in the ensemble, and the acceptance drops.
- **Slow decorrelation.** If there are several channels separated in path space, the path chain may stay in one channel. Check with several initial paths.
- **Shooting with the wrong backward dynamics.** For a dynamics that is not reversible, using the forward step backward breaks detailed balance.
- **The initial path.** A path forced over the barrier by an artificial bias is not typical. Discard the early moves.

## History

Dellago, Bolhuis, Csajka and Chandler gave transition path sampling in 1998, with the shooting and shifting moves for stochastic dynamics and the computation of rate constants from the correlation function. The method was extended to deterministic dynamics and to many applications in the following years, and Bolhuis, Chandler, Dellago and Geissler reviewed it in 2002. Transition interface sampling and [forward flux sampling](/forward-flux-sampling/) later used interfaces between the states to compute rates more efficiently.
