---
title: The Penn Treebank rules only insert spaces and rewrite double quotes, and they isolate each punctuation mark
proves: [correctness, termination]
status: full
---

A rule set has no "right answer" to prove against: the Penn Treebank convention is defined by its rules. What can be proved is that the procedure applies the rules of the sed script, and that its output has the properties that the convention promises. Let $x$ be one line with no line break. A *space* below is the character U+0020 or a tab. For a string $y$, let $\sigma(y)$ be $y$ with all spaces removed. Let $S$ be the set of the 18 characters in `,;:@#$%&?!()[]{}<>`. The open quote token is ` `` ` (two backquotes) and the close quote token is ` '' ` (two apostrophes).

**Lemma 1 (the translation).** Each line of the pseudocode applies the same substitutions as the matching lines of the sed script, in the same order, so the Python function returns the token list of the script.

*Proof.* The sed script uses basic regular expressions in the form `s=pattern=replacement=g`. Line L1 is the first rule, which replaces a double quote at the start by the open quote and a space. Line L2 is `\([ ([{<]\)"`, which is the Python pattern `([ (\[{<])"` with the group `\1`. Line L3 is the rule for `...` and the rule for the class `[,;:@#$%&]`, where the sed replacement `&` (the whole match) is `\g<0>` in Python. Line L4 is the final period rule `\([^.]\)\([.]\)\([])}>"']*\)[ <tab>]*$`. A bracket expression that starts with `]` holds that character, so the Python class is `[\])}>"']`. Line L5 is `[?!]`, then `[][(){}<>]` (a class that holds both square brackets), then `--`. Line L6 is `s=$= =` and `s=^= =`. Line L7 replaces each remaining double quote by a space, the close quote and a space. Line L8 is the rule for a closing single quote, the rule for `'s`, `'m` and `'d` in both cases, and the eight rules for `'ll`, `'re`, `'ve`, `n't`, `'LL`, `'RE`, `'VE` and `N'T`. Line L9 is the ten rules for cannot, d'ye, gimme, gonna, gotta, lemme, more'n, 'tis, 'twas and wanna. The last two sed rules squeeze runs of spaces and delete leading spaces; splitting at runs of white space in line L10 gives the same list of fields. Python `re.sub` replaces the leftmost non-overlapping matches from left to right, which is the meaning of the `g` flag in sed. Without a line break in the input, `^` and `$` mean the two ends of the string in both. $\square$

**Lemma 2 (only spaces are added).** Let $y_0 = x$, and let $y_t$ be the string after the $t$-th substitution. Then $\sigma(y_t)$ is $\sigma(x)$ with some of its double quotes replaced, each by the open quote or by the close quote, and after line L7 every double quote of $x$ is replaced.

*Proof.* By induction on $t$. Inspect each replacement. Every rule writes back the characters it matched, in the same order, with spaces added, except in three cases. Lines L1 and L2 write the open quote in place of a matched double quote. Line L7 writes the close quote in place of each remaining double quote. The final period rule of line L4 drops the spaces and tabs that it matched at the end of the line, which does not change $\sigma$. The rules of line L9 add one space inside the matched word, for example "can not" for "cannot" and "'T is" for "'Tis". After line L7 no double quote is left. $\square$

**Lemma 3 (punctuation stands alone).** Each character of $S$ in $x$ ends up as a token of length 1.

*Proof.* Line L3 puts a space on both sides of each of the eight characters of `,;:@#$%&`, and line L5 does the same for `?`, `!` and the eight brackets. A rule that removes spaces would be needed to join such a character to a neighbour. The only rule that removes spaces is the final period rule of line L4, and it removes only spaces at the end of the line that follow a period or one of the closing marks `)]}>"'`. None of these is one of the eight characters of line L3, and the brackets get their spaces from line L5, which runs later. So in the final string each character of $S$ has a space or an end of the string on both sides, and line L10 makes it a token. $\square$

**Lemma 4 (clitics).** If the string before line L8 has a word that ends in n't, 's, 'm, 'd, 'll, 're or 've (in lower case, or in the upper case forms of the script) and is followed by a space, then the clitic is a separate token at the end.

*Proof.* Line L6 makes sure that the last word of the string is followed by a space. The rule for the clitic matches it at the end of the word, because the pattern needs the space after it, and the replacement puts a space in front of it. By Lemma 2, no later rule removes a space. $\square$

**Theorem.** PTB-TOKENIZE$(x)$ stops after a fixed number of passes over the string, and returns the tokens of the sed script of MacIntyre for the line $x$. If $x$ contains neither two backquotes nor two apostrophes in a row, then the concatenation of the tokens, with each open and close quote token written as a double quote, is $\sigma(x)$, and each character of $S$ is a token by itself.

*Proof.* There are 29 substitutions and two padding steps, each a single left to right pass, so the procedure stops. The first claim is Lemma 1. Line L10 splits the final string $y$ at runs of spaces, so the concatenation of the tokens is $\sigma(y)$. By Lemma 2, $\sigma(y)$ is $\sigma(x)$ with each double quote replaced by an open or a close quote. By the hypothesis on $x$, a token is an open or a close quote only if it came from a double quote, so writing these tokens back as double quotes gives $\sigma(x)$. The last claim is Lemma 3. $\blacksquare$

**Remark.** The theorem does not say that the tokens are linguistically right. The script splits off only a period at the end of the line. So "it. You" stays "it." and "You" when the input holds two sentences, and a final abbreviation loses its period: "the U.S." gives "U.S" and ".". These follow from line L4. They are part of the convention, not errors in the proof.
