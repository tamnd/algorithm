---
title: UTF-8 encoding is a bijection onto Table 3-7, and the decoder replaces exactly the maximal subparts
proves: [correctness, termination]
status: full
---

**Claim.** (a) For every Unicode scalar value $c$, UTF8-ENCODE$(c)$ (lines L1 to L4) is a byte sequence of Table 3-7 of the core specification, and every sequence of the table is the encoding of exactly one scalar value. (b) For every byte string $B$ of length $n$, UTF8-DECODE$(B)$ (lines L5 to L18) stops. If $B$ is well-formed UTF-8, the output is the sequence of scalar values that $B$ encodes. If not, the output has one U+FFFD for each maximal subpart (D93b) that the left-to-right scan meets, and the scalar values of the well-formed sequences between them.

**Setup.** Table 3-7 has nine rows. Each row is a product of byte ranges: a first byte range, a second byte range, and the range 0x80..0xBF for every later byte. The rows are 00..7F; C2..DF, 80..BF; E0, A0..BF, 80..BF; E1..EC, 80..BF, 80..BF; ED, 80..9F, 80..BF; EE..EF, 80..BF, 80..BF; F0, 90..BF, 80..BF, 80..BF; F1..F3, 80..BF, 80..BF, 80..BF; F4, 80..8F, 80..BF, 80..BF. The first byte ranges of the rows do not overlap, so the first byte fixes the row and the length. LEAD-INFO$(b)$ returns, for a first byte $b$ of a multi-byte row, the number $k$ of bytes after it and the range $lo..hi$ of the second byte, and $k = 0$ for the bytes 80..C1 and F5..FF, which start no row.

**Lemma 1 (encoding).** Let $c$ be a scalar value. Line L1 handles $c < 2^7$ with one byte $c$, which is in row 1. Line L2 handles $2^7 \le c < 2^{11}$. The first byte is $\mathtt{110}$ followed by the high 5 of the 11 bits of $c$, and these 5 bits are at least $00010$ because $c \ge 2^7$, so the first byte is in C2..DF. The second byte is $\mathtt{10}$ followed by the low 6 bits. Line L3 handles $2^{11} \le c < 2^{16}$, and the first byte is E0 plus the high 4 bits $c_h$ of the 16. If $c_h = 0$, then $c \ge 2^{11}$ forces the next 6 bits to be at least $100000$, so the second byte is in A0..BF. If $c_h = \mathtt{D}$, then $c < \mathtt{D800}$ (a scalar value is not a surrogate) forces those 6 bits below $100000$, so the second byte is in 80..9F. Line L4 handles $2^{16} \le c \le \mathtt{10FFFF}$. The high 3 of the 21 bits are 0 to 4. If they are 0, then $c \ge 2^{16}$ forces the next 6 bits to be at least $010000$, so the second byte is in 90..BF. If they are 4, then $c \le \mathtt{10FFFF}$ forces those 6 bits to be at most $001111$, so the second byte is in 80..8F. In every case the bytes after the second are $\mathtt{10}$ followed by 6 bits of $c$. So the output is in the row for its length.

Conversely, a sequence of a row of length $L$ carries $7$, $11$, $16$ or $21$ payload bits for $L = 1, 2, 3, 4$, and the range limits of the row are exactly the conditions above in reverse. So its payload, read as a number, is a scalar value $c$ in the range of line L1, L2, L3 or L4, and that line writes the same bits back. Two different scalar values have different payload bits, so the map is injective, and by the converse it is onto. $\square$

**Lemma 2 (one step of the scan).** Let $0 \le i < n$ and let $b = B[i]$. One iteration of the loop of line L6 does one of these things.

1. $b < \mathtt{80}$ (line L8). $B[i]$ alone is a sequence of row 1. The iteration outputs $b$ and sets $i \leftarrow i + 1$.
2. $k = 0$ (line L10). $b$ is the first byte of no row, so no well-formed sequence starts at $i$ and the maximal subpart at $i$ is $B[i]$ alone. The iteration outputs U+FFFD and sets $i \leftarrow i + 1$.
3. $k \ge 1$. The inner loop of lines L12 to L15 keeps this invariant: $B[i \ldots i+j-1]$ is a prefix of a sequence of the row of $b$, and $c$ holds its payload bits. Line L11 sets it up for $j = 1$, and line L15 keeps it, because line L14 lets $j$ grow only when $B[i+j]$ is in the range of position $j$ of the row. If the loop ends with $j = k + 1$, the whole row matched, and by Lemma 1 the iteration outputs the scalar value that these $k + 1$ bytes encode. If it ends at line L14 with $j \le k$, then $B[i \ldots i+j-1]$ is a prefix of a well-formed sequence, and $B[i \ldots i+j]$ is not, because byte $i + j$ is missing or out of range for its position. As each row is a product of ranges, any byte in the range is allowed whatever the earlier bytes are, so no longer prefix exists. So $B[i \ldots i+j-1]$ is the maximal subpart at $i$, and the iteration outputs one U+FFFD. In both cases line L17 sets $i \leftarrow i + j$ with $j \ge 1$.

**Proof of (a).** Lemma 1.

**Proof of (b), termination.** By Lemma 2, every iteration of the outer loop raises $i$ by at least 1, and the inner loop runs at most $k \le 3$ times. So the loop of line L6 runs at most $n$ times and the procedure stops at line L18.

**Proof of (b), output.** If $B$ is well-formed, it is a concatenation of sequences of the table. No sequence of the table is a proper prefix of another, because the first byte fixes the length. So by induction on the number of iterations, each iteration starts at the first byte of one of these sequences, and by case 1 or case 3 of Lemma 2 it outputs the scalar value of that sequence and moves to the next one. If $B$ is ill-formed, the same lemma shows that each iteration either outputs one whole well-formed sequence or one U+FFFD for the maximal subpart at the current position, and then resumes right after it. This is the practice of section 3.9.6, "U+FFFD Substitution of Maximal Subparts". In strict mode, the first case 2, or case 3 with $j \le k$, raises an error whose bounds are $i$ and $i + j$, the bounds of that maximal subpart. $\blacksquare$

**Corollary (order).** For scalar values $c < d$, the encoding of $c$ is smaller than the encoding of $d$ in the byte-wise lexicographic order. If the two encodings have the same length, their bytes hold the payload bits from high to low behind the same fixed prefixes, so the first byte that differs compares like $c$ and $d$. If $c$ has the shorter encoding, its first byte is smaller, because the first byte ranges of rows of length 1, 2, 3, 4 are 00..7F, C2..DF, E0..EF and F0..F4, in this order.
