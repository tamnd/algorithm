---
title: Index nested-loop join returns the join as a multiset, and its cost is M plus the probe costs
proves: [correctness, termination, io.worst]
status: full
---

We use the line numbers of the pseudocode. We treat each stored tuple as a distinct occurrence, and each tuple of $S$ has a distinct record id $(q, i)$: page $q$, slot $i$. The join $R \bowtie S$ on $r.a = s.b$ is the multiset with one copy of $r \cdot s$ for each pair of occurrences with $r.a = s.b$.

**The index.** The index holds one entry $(s.b, \mathrm{rid}(s))$ for each tuple $s$ of $S$. We prove that SEARCH returns exactly the record ids of the tuples with $b = v$, for a B+ tree as in the implementation. A hash index is the special case where the bucket of $v$ holds every entry with key $v$, and a search that reads the whole bucket chain and filters on the key returns exactly those entries.

The B+ tree stores its entries in leaves $L_1, \ldots, L_t$, from left to right, in order of $(\text{key}, \mathrm{rid})$. Each inner node stores, for each child, the largest key in the subtree of that child. Each leaf also stores the smallest key of the next leaf (a fence key). The search for $v$ starts at the root, and at each inner node goes to the first child whose largest key is at least $v$. If there is no such child, it returns the empty set. At the leaf level it collects the entries with key $v$ from this leaf, and it moves to the next leaf only while the fence key of the current leaf equals $v$.

**Lemma 1 (search).** SEARCH$(I, v)$ returns the record ids of exactly the tuples of $S$ with $b = v$, each once.

*Proof.* Let $E_v$ be the set of entries with key $v$. Because the leaves are sorted, $E_v$ is a contiguous run of entries in the leaf order. If $E_v$ is empty, the search returns nothing: either it stops at an inner node with the empty set, or it collects only entries with key $v$, of which there are none. Assume $E_v$ is not empty, and let $e$ be its first entry, in leaf $L_j$. We show by induction on the depth that the search reaches an ancestor of $L_j$ at each level. The root is an ancestor of every leaf. Let the search be at an ancestor $X$ of $L_j$, and let $Y$ be the child of $X$ that contains $L_j$. Every child of $X$ to the left of $Y$ holds only entries before $e$ in the sorted order, so all their keys are less than $v$, and so their largest keys are less than $v$. The largest key of $Y$ is at least the key of $e$, which is $v$. So the first child with largest key at least $v$ is $Y$, and the search goes to $Y$. At the leaf level, the search is at $L_j$. The entries of $L_j$ before $e$ have keys less than $v$ and are not collected. The scan collects the entries of $L_j$ with key $v$. If $E_v$ goes on into the next leaf, the first key of the next leaf is $v$, so the fence key equals $v$ and the scan moves on. If it does not, the first key of the next leaf is larger than $v$ (or there is no next leaf), and the scan stops. By induction over the leaves, the scan visits exactly the leaves that hold entries of $E_v$, starting at $L_j$, and collects each entry of $E_v$ once and nothing else. Each entry corresponds to one tuple of $S$ with $b = v$. $\square$

**Theorem 1 (correctness).** INDEX-NESTED-LOOP-JOIN returns a list whose multiset of elements is $R \bowtie S$.

*Proof.* Lines L2 and L4 meet each occurrence $r$ of $R$ exactly once, because the pages partition $R$. For this $r$, by Lemma 1, line L5 returns the record ids of exactly the tuples $s$ of $S$ with $s.b = r.a$, each once. Line L6 visits each of them once, and line L9 appends $r \cdot s$ for it. Lines L7 and L8 only read a page and do not change $out$. So for each tuple $t$, the number of copies of $t$ in $out$ is the number of pairs $(r, s)$ with $r.a = s.b$ and $r \cdot s = t$. All loops are finite, so the algorithm stops. $\blacksquare$

**Theorem 2 (I/O count).** Let $C(r)$ be the number of reads done by lines L5 to L8 for the tuple $r$. The algorithm does exactly $M + \sum_{r \in R} C(r)$ reads. For a B+ tree with $h$ inner levels, $C(r) = h + \ell(r) + f(r)$, where $\ell(r) = \max(1, \text{the number of leaves holding } r.a)$, except that a key larger than every key stops at the root after one read. Here $f(r)$ is the number of matches $k(r)$ for an unclustered index, or the number of distinct pages among the matches for a clustered index. If every probe costs $C$, the total is $M + p_R M C$.

*Proof.* Reads happen at line L3, once per page of $R$, which is $M$ reads, and inside lines L5 to L8. The search reads one node per inner level, $h$ in all, and then, by the proof of Lemma 1, the leaf $L_j$ it reaches and each further leaf that holds the key. If the key is larger than every key, the largest key of the root is less than it, and the search stops after reading the root. Line L8 reads a page for each record id when the index is unclustered. When it is clustered, the matches are in page order, so the matches on one page are consecutive in $E$, and line L7 reads each distinct page exactly once. Summing over the $p_R M$ tuples of $R$ gives the formula. $\blacksquare$
