---
title: Normalized Polish expressions are exactly the postorders of skewed slicing trees
proves: [correctness, bijection, complexity]
status: full
---

We use the pseudocode and the conventions of the page. A *slicing tree* on a set $B$ of $n$ blocks is a full binary tree whose leaves are the blocks, each one time, and whose internal nodes carry an operator $H$ or $V$. It is *skewed* if no internal node has a right child that is an internal node with the same operator. A *Polish expression* is a word that is the postorder of some slicing tree.

**Lemma 1 (Polish expressions).** A word $E = e_1 \cdots e_m$ over $B \cup \{H, V\}$ in which each block occurs exactly one time is a Polish expression if and only if $m = 2n - 1$ and every prefix $e_1 \cdots e_k$ has more operands than operators (the balloting property). The tree is then unique, and lines L9 to L15 build it.

*Proof.* Let $c_k$ be the number of operands minus the number of operators in $e_1 \cdots e_k$. Lines L10 to L15 push one item for an operand and replace two items by one for an operator, so after step $k$ the stack holds $c_k$ items if no pop failed. A pop fails at step $k$ exactly when $c_{k-1} < 2$, that is when $c_k < 1$. So the loop runs to the end if and only if the balloting property holds, and then the stack holds $c_m$ items. With $n$ operands, $c_m = 1$ if and only if there are $n - 1$ operators, that is $m = 2n - 1$. In that case the single item is a full binary tree whose postorder is $E$, by induction on $k$: each stack item is a tree whose postorder is a factor of $E$, and these factors in stack order make up $e_1 \cdots e_k$.

Conversely, the postorder of a full binary tree with $n$ leaves has $2n - 1$ tokens, and each prefix is the postorder of a forest of $j \ge 1$ trees followed by nothing, so it has $j$ more operands than operators. The tree of a Polish expression is unique, because the stack procedure is forced: the last token is the root, and the run of the stack decides the two subtrees. $\square$

**Lemma 2 (right children in postorder).** Let $u$ be an internal node of a full binary tree, at position $k$ of the postorder. Then $e_{k-1}$ is the right child of $u$.

*Proof.* The postorder of the subtree of $u$ is the postorder of the left subtree, then the postorder of the right subtree, then $u$. The last token of the postorder of a subtree is its root. $\square$

**Theorem 1 (VALID).** VALID returns true if and only if $E$ is the postorder of a skewed slicing tree on $B$. Hence the map from skewed slicing trees to their postorders is a bijection onto the normalized Polish expressions.

*Proof.* Line L1 checks that the operands are the blocks, each one time, and that $m = 2n - 1$. Lines L2 to L7 compute $c_k$ and stop if $c_k < 1$ after an operator. Before the first operator $c_k \ge 1$, so the loop checks the balloting property; by Lemma 1, $E$ passes these tests if and only if it is a Polish expression of a unique tree $T$. Line L7 also rejects $E$ if two equal operators are next to each other. If $e_{k-1}$ and $e_k$ are both operators, then by Lemma 2 the node $e_{k-1}$ is an internal right child of $e_k$. If $e_{k-1}$ is an operand, the right child of $e_k$ is a leaf. So $E$ has two equal operators next to each other if and only if some internal node of $T$ has an internal right child with the same operator, that is if and only if $T$ is not skewed. The map is one to one by the uniqueness in Lemma 1, and onto by this equivalence. $\square$

**Lemma 3 (EVALUATE).** EVALUATE returns the width and the height of the floorplan of $T$ and a placement of the blocks without overlap inside the $W \times H$ rectangle, in which each block is at the lower-left corner of its room.

*Proof.* By Lemma 1, the stack loop builds $T$. By induction on the height of a node $t$, the values $W_t$ and $H_t$ of lines L13 and L14 are the width and height of the smallest rectangle that holds the floorplan of the subtree of $t$: a vertical cut puts the two parts side by side, so the widths add and the height is the larger height; a horizontal cut puts the first part below the second, and the roles change. PLACE gives the subtree of $t$ the rectangle $[x, x + W_t) \times [y, y + H_t)$. For a $V$ node it gives the left part $[x, x + W_a) \times [y, y + H_a)$ and the right part $[x + W_a, x + W_a + W_b) \times [y, y + H_b)$, which are inside the rectangle of $t$ and are separated by the line $X = x + W_a$. The $H$ case is the same with the roles of $x$ and $y$ changed. So by induction each block gets a rectangle inside the room of its leaf, the rooms of two different leaves are separated by the cut of their lowest common ancestor, and no two blocks overlap. $\square$

**Lemma 4 (NORMALIZE).** NORMALIZE returns a normalized Polish expression whose floorplan is the floorplan of the input, and two Polish expressions have the same normalized form if and only if one can be changed into the other by the associative law $(a\,o\,b)\,o\,c = a\,o\,(b\,o\,c)$ inside the tree.

*Proof.* For a node $t$ with operator $o$, line L24 collects the maximal subtrees $c_1, \ldots, c_k$ below $t$ that are reached through $o$-nodes only and whose roots are leaves or nodes with the other operator. The subtree of $t$ puts $c_1, \ldots, c_k$ side by side in this order (for $V$) or on top of each other in this order (for $H$), whatever the shape of the $o$-chain, because the operator is associative on rectangles: both sides of the associative law have width $W_a + W_b + W_c$, height $\max(H_a, H_b, H_c)$ and the same order of parts, and the same for $H$. Line L25 emits the left-deep chain $((c_1\,o\,c_2)\,o\,c_3) \cdots o\,c_k$. In this chain every right child is some $c_i$, which is a leaf or has the other operator. By induction on the subtrees, each $c_i$ is emitted in normalized form, so the whole tree is skewed and its postorder is normalized by Theorem 1. The floorplan is the same by associativity, applied inside each chain.

The ordered list $c_1, \ldots, c_k$ of each maximal chain does not change under the associative law, and two trees with the same chains at every level are related by the associative law, because both can be brought to the left-deep form. So the normalized form is the same exactly for associatively equal trees. $\square$

**Theorem 2 (counts).** The number of normalized Polish expressions on $n$ blocks is $n!\,S_{n-1}$, where $S_k$ is the $k$th large Schröder number $1, 2, 6, 22, 90, 394, \ldots$ for $k = 0, 1, 2, \ldots$.

*Proof.* By Theorem 1 and Lemma 4, normalized expressions with a fixed left to right order of the leaves are in bijection with the ordered trees in which every internal node has at least two children, the leaves are the blocks in this order, and the internal nodes carry operators that alternate between a node and its internal children. Such a tree is fixed by its shape and the operator of the root, and the shape is a plane tree with $n$ leaves and no node with one child. The number of these shapes is the little Schröder number $s_n = 1, 1, 3, 11, 45, 197$ for $n = 1, \ldots, 6$, and $S_{n-1} = 2 s_n$ for $n \ge 2$ (OEIS A001003 and A006318, which list this interpretation). With the $n!$ orders of the leaves, the count is $n!\,S_{n-1}$. The tests check the values $1, 4, 36, 528, 10800$ for $n \le 5$ against all words. $\square$

**Complexity.** VALID reads each token one time. EVALUATE does one push for each operand, one pair of pops and one push for each operator, and PLACE visits each of the $2n - 1$ nodes one time. NORMALIZE builds the tree in $O(n)$ time and visits each node a constant number of times. So each operation takes $O(n)$ time and $O(n)$ space. $\blacksquare$
