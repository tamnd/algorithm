We use the notation and the line numbers of the page. $\mathrm{DH}(a, B)$ is X25519 of the private key $a$ and the public key $B$. KDF_RK and KDF_CK are the HKDF and HMAC steps of the page. For the security statements we model KDF_RK and KDF_CK as random oracles and assume that the Diffie-Hellman problem on X25519 is hard; this is the setting of Cohn-Gordon et al. (J. Cryptology 2020).

**Lemma 1 (X3DH agreement).** If Alice uses the bundle that Bob published and Bob still holds the one-time prekey, both compute the same $SK$ and the same associated data.

*Proof.* Alice computes $\mathrm{DH}(IK_A, SPK_B)$, $\mathrm{DH}(EK_A, IK_B)$, $\mathrm{DH}(EK_A, SPK_B)$ and $\mathrm{DH}(EK_A, OPK_B)$ in line L3. Bob computes $\mathrm{DH}(SPK_B, IK_A)$, $\mathrm{DH}(IK_B, EK_A)$, $\mathrm{DH}(SPK_B, EK_A)$ and $\mathrm{DH}(OPK_B, EK_A)$ in line L5. X25519 is symmetric: $\mathrm{DH}(a, g^b) = \mathrm{DH}(b, g^a)$, because both are the $u$-coordinate of $[ab]$ times the base point (the clamped scalars commute). So the four values are equal and in the same order, and the deterministic KDF gives the same $SK$. Both sides set $AD = IK_A \| IK_B$. $\square$

**Lemma 2 (the ratchet states match).** Call a session pair *synchronized* when, for each direction, the receiver's root key and ratchet keys are those that the sender used for its current sending chain, or the receiver already holds the message keys of every message that it has not yet received. After lines L4 and L6, Alice and Bob are synchronized, and each honest send and each honest receive keeps them synchronized.

*Proof.* At the start, Alice holds $RK_1, CK_s$ from KDF_RK$(SK, \mathrm{DH}(DH_A, SPK_B))$ and Bob holds $SK$ and the key pair of $SPK_B$. When Bob receives a header with the new key $DH_A$, line L10 computes KDF_RK$(SK, \mathrm{DH}(SPK_B, DH_A))$, which equals Alice's value by the symmetry of X25519, so Bob's receiving chain equals Alice's sending chain. The same holds at every later DH ratchet step: the receiver computes the root key update from its own private ratchet key and the sender's new public key, which equals the sender's computation from the other two keys, and then both sides chain KDF_RK from equal root keys. Inside one chain, KDF_CK is deterministic, so the $n$-th message key is the $n$-th output for both sides. A send changes only the sender's state, along the chain that the receiver can follow. $\square$

**Theorem 3 (every honest message decrypts once, in any order).** Suppose all messages are sent honestly and delivered unchanged, in any order, and that no receive needs more than MAX_SKIP skipped keys. Then each message decrypts to its plaintext exactly once.

*Proof.* Take a message with header $(D, pn, n)$. If its key was stored as skipped, line L8 finds it under $(D, n)$ and deletes it after use. If $D$ is the current receiving key, line L11 advances the chain to position $n$, storing the keys of the positions it passes, and uses the key at $n$; by Lemma 2 it equals the sender's key. If $D$ is new, the sender has made a new chain after the receiver's last ratchet key, and $pn$ is the length of the sender's previous chain; line L9 stores the remaining keys of that chain, then line L10 makes the new chain, which by Lemma 2 equals the sender's. Each message key is used for one header and then removed (from the skipped table, or by advancing the chain), so a second delivery fails. A late message of an older chain finds its key in the skipped table, because the receiver stored all keys of that chain up to $pn$ when it moved on. $\square$

**Theorem 4 (forward secrecy of message keys).** An attacker who learns the full state of a party at some time, and has recorded all ciphertexts, learns no message key of a message that the party had already received or sent before that time, except the keys still stored as skipped.

*Proof.* A message key $mk_n$ of a chain is KDF_CK$(CK_n)$ with the constant 0x01, and the chain key moves on as $CK_{n+1} = $ KDF_CK$(CK_n)$ with the constant 0x02. After the message, the state holds only chain keys $CK_m$ with $m > n$, root keys of later steps, and the skipped keys. In the random oracle model, $CK_n$ is independent of $CK_{n+1}$ given only $CK_{n+1}$, so $mk_n$ is hidden unless the attacker queries the oracle at $CK_n$, which it does not know. Old root keys are hidden in the same way, because each root key is an output of KDF_RK and the state no longer holds its input. The one-time prekey is deleted in line L5 and the ephemeral key after line L3, so the long-term keys do not give $SK$ again. $\square$

**Theorem 5 (healing after a compromise).** Suppose an attacker copies Alice's whole state at time $t$ and then only watches the network. After Alice receives a message from Bob with a new ratchet key and sends a message with her new ratchet key, and Bob replies, the attacker cannot compute the message keys of that message of Alice, of Bob's reply, or of any later message, unless it solves a Diffie-Hellman instance.

*Proof.* Let $a$ be Alice's ratchet private key at time $t$. Bob's next DH ratchet step uses his fresh key $b$ with $g^a$, so the attacker, who holds $a$, follows it: this is the one step that is not healed. When Alice receives $g^b$, line L10 makes her fresh key $a'$, chosen after the compromise, and the new root key is KDF_RK$(RK, g^{a'b})$. The attacker sees $g^{a'}$ and $g^b$ but holds neither $a'$ nor $b$. Computing $g^{a'b}$ from them is the Diffie-Hellman problem. In the random oracle model, an attacker that does not query KDF_RK at $(RK, g^{a'b})$ sees the new root key and the new chain keys as uniform. All later root keys are derived from this one and from fresh ratchet keys, so the same holds for them. $\square$

Theorems 4 and 5 assume that the attacker only reads the network after the compromise. An active attacker with the state of $t$ can instead impersonate Alice to Bob, as each protocol must allow, since the state is all Alice knows; healing then fails for that session. $\blacksquare$
