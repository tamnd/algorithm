A term is in A-normal form (ANF) when every operand of every call and operator is a variable or a constant, and every intermediate result is named by a `let`. So `f (g x) + 1` becomes `let t1 = g x in let t2 = f t1 in t2 + 1`. The form is in direct style: functions return their results, and there are no continuations. Yet it has what compiler writers wanted from [continuation-passing style](/continuation-passing-style/): the order of evaluation is fixed by the nesting of `let`s, and every value that a later step uses has a name. Flanagan, Sabry, Duba and Felleisen (1993) defined the form and named it after the A-reductions that produce it. They showed that a compiler that translates to CPS, simplifies, and translates back gets exactly the A-normal form. For a language without first-class functions, ANF is close to [three-address code](/three-address-code/), with nesting in place of jumps.

## Definition

Take a call-by-value [lambda calculus](/lambda-calculus/) with constants, operators $\oplus$, `let` and `if`. A term $M$ is in **A-normal form** if it is generated by:

$$
\begin{aligned}
V &::= c \mid x \mid \lambda x.\,M && \text{(values)}\\
C &::= V \mid V_1\,V_2 \mid V_1 \oplus V_2 && \text{(simple computations)}\\
M &::= C \mid \mathtt{let}\ x = C\ \mathtt{in}\ M \mid \mathtt{if}\ V\ \mathtt{then}\ M_1\ \mathtt{else}\ M_2 && \text{(terms)}
\end{aligned}
$$

So the right side of a `let` is never a `let` or an `if`, operands and conditions are values, and the body of every function is again in A-normal form. A call $V_1\,V_2$ in the position of $C$ at the end of a term, not on the right of a `let`, is a tail call.

**A-reductions.** Let $E$ be a call-by-value evaluation context, $E ::= [\,] \mid E\,M \mid V\,E \mid E \oplus M \mid V \oplus E \mid \mathtt{let}\ x = E\ \mathtt{in}\ M \mid \mathtt{if}\ E\ \mathtt{then}\ M_1\ \mathtt{else}\ M_2$, with $E \ne [\,]$ in the rules below:

- **(A1)** $E[\mathtt{let}\ x = M\ \mathtt{in}\ N] \to \mathtt{let}\ x = M\ \mathtt{in}\ E[N]$, where $x$ is not free in $E$.
- **(A2)** $E[\mathtt{if}\ V\ \mathtt{then}\ M_1\ \mathtt{else}\ M_2] \to \mathtt{if}\ V\ \mathtt{then}\ E[M_1]\ \mathtt{else}\ E[M_2]$.
- **(A3)** $E[C] \to \mathtt{let}\ t = C\ \mathtt{in}\ E[t]$, where $C$ is a call or an operation, $t$ is new, and $E$ is not of the form $E'[\mathtt{let}\ z = [\,]\ \mathtt{in}\ N]$, so that the hole is not already the right side of a `let`.

Applied anywhere in a term until none applies, they give a term in A-normal form. Rule A1 flattens nested `let`s, rule A2 moves the work after a conditional into both branches, and rule A3 names an intermediate result.

**A-normalization keeps the meaning.** Each rule is an equation of call-by-value evaluation. The key fact is that $E[M]$, for an evaluation context $E$, runs $M$ first: if $M$ ends with a value $v$, then $E[M]$ continues as $E[v]$; if $M$ is stuck or runs forever, so is $E[M]$.

- For A3, both sides run $C$ first. If it gives $v$, the left side continues as $E[v]$ and the right side as $E[t][t := v] = E[v]$, since $t$ is new.
- For A1, both sides run $M$ first. If it gives $v$, the left side continues as $E[N[x := v]]$ and the right side as $E[N][x := v]$. These are the same term, because $x$ is not free in $E$.
- For A2, $V$ is already a value. If it is `true`, both sides continue as $E[M_1]$; if `false`, as $E[M_2]$; otherwise both are stuck.

The same holds after a substitution of closed values for the free variables and inside any further evaluation context, because the argument uses only the order of evaluation and substitution. So the two sides of each rule have the same outcome in every program, and a rule may be applied under a `fun` or in a branch. A sequence of A-reductions therefore keeps the outcome of the program: the same constant, stuck in both, or no end in both.

A direct algorithm reaches the same normal form in one pass. Flanagan et al. give one that walks the term once with a translation-time continuation for the context, as the one-pass [CPS conversion](/cps-conversion/) does. Its output is linear in the input except for the copies that rule A2 makes.

## Examples and non-examples

**Nested calls.** `f (g x) (h y)` has the normal form `let t1 = g x in let t2 = h y in f t1 t2` (with a curried `f`, `let t3 = f t1 in t3 t2`). The `let`s fix the order: `g x` runs before `h y`, as call-by-value from left to right says.

**Nested `let`.** `let x = (let y = a + 1 in y * 2) in x - 3` becomes `let y = a + 1 in let x = y * 2 in x - 3` by rule A1 and then A3.

**Conditional in an operand.** `(if a then b else c) + 1` becomes `if a then b + 1 else c + 1` by rule A2. The context `[ ] + 1` is copied into both branches. With a large context and many nested conditionals the copies grow without bound. Compilers give the context a name instead, a *join point* `let j = fun r -> r + 1 in if a then j b else j c`, where every use of `j` is a tail call (Maurer, Downen, Ariola and Peyton Jones 2017).

**Functions.** `map (fun x -> x * x + 1) xs` is `map (fun x -> let t = x * x in t + 1) xs` in normal form: the function is a value, and only its body changes.

**Non-examples.**

- `f (g x)`: the operand `g x` is not a value.
- `let x = (let y = a in b) in c`: the right side of a `let` is a `let`.
- `if x < 1 then a else b`: the condition is not a value. Its normal form is `let t = x < 1 in if t then a else b`.
- `let y = (if a then b else c) in y + 1`: the right side is an `if`. The definition above forbids it. Some variants allow it, as a join point in disguise.
- `g x (fun v -> k v)`: this is a CPS call, not ANF. ANF has no continuation arguments.

## Related definitions

- **[Continuation-passing style](/continuation-passing-style/).** The CPS image of an A-normal form term needs no administrative redexes, and translating CPS terms without administrative redexes back to direct style gives A-normal forms. Sabry and Felleisen (1993) showed that the A-reductions are what the administrative reductions of CPS do, seen in the source.
- **[CPS conversion](/cps-conversion/).** Its one-pass form is A-normalization with a continuation argument added. Kennedy (2007) argues that CPS is still the better intermediate language, because ANF is not closed under inlining: putting a function body with `let`s in the place of a call on the right of a `let` breaks the form, and the term must be normalized again.
- **[Static single assignment form](/static-single-assignment-form/).** Every name in ANF is bound once, as in SSA. Chakravarty, Keller and Zadarnowski (2003) translate SSA programs into ANF, with blocks as local functions and phi-functions as parameters. The [correspondence of SSA and functional programs](/ssa-cps-correspondence/) states this.
- **[Three-address code](/three-address-code/).** A three-address instruction `t = a op b` is the ANF binding `let t = a op b`. ANF adds nesting, local functions and lexical scope.
