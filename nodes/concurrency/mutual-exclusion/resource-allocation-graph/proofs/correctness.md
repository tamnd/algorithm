**Setting.** The graph has processes $P$ with $|P| = n$, resource types $R$ with $|R| = m$, and $t(r) \ge 1$ units of each type $r$. For each $p$ and $r$, $\mathit{held}[p][r]$ is the number of assignment edges $r \to p$ and $\mathit{req}[p][r]$ the number of request edges $p \to r$. The free units are $\mathit{avail}[r] = t(r) - \sum_p \mathit{held}[p][r]$. We assume the precondition of REQUEST: $\mathit{held}[p][r] + \mathit{req}[p][r] \le t(r)$ for all $p, r$. A process is *blocked* when $\mathit{req}[p][r] > \mathit{avail}[r]$ for some $r$. A blocked process takes no step, so it neither releases a unit nor changes its requests. A process that is not blocked may get its requests and later release all its units. A reduction step removes a process $p$ with $\mathit{req}[p] \le \mathit{work}$ (componentwise) and adds $\mathit{held}[p]$ to $\mathit{work}$, where $\mathit{work}$ starts as $\mathit{avail}$. The page on [deadlock detection](/deadlock-detection/) proves that the set $L$ of processes that no reduction removes does not depend on the order of the steps, and that $L$ is exactly the set of deadlocked processes.

**Lemma 1 (the invariant).** NEW, REQUEST, GRANT and RELEASE keep $\mathit{avail}[r] = t(r) - \sum_p \mathit{held}[p][r] \ge 0$ for every $r$.

*Proof.* NEW sets $\mathit{avail} = t$ and $\mathit{held} = 0$. REQUEST changes neither side. GRANT runs line L4 only when line L3 found $\mathit{req}[p][r] \le \mathit{avail}[r]$ for all $r$; it moves $\mathit{req}[p][r]$ units from $\mathit{avail}[r]$ to $\mathit{held}[p][r]$, so the sum stays fixed and $\mathit{avail}[r]$ stays $\ge 0$. RELEASE with $k \le \mathit{held}[p][r]$ moves $k$ units back, so the sum stays fixed and $\mathit{held}[p][r] \ge 0$. $\square$

**Lemma 2 (a deadlock contains a cycle).** If $L \ne \emptyset$, the wait-for graph restricted to $L$ has a cycle. So every deadlock contains a cycle of the resource allocation graph, for any numbers of units.

*Proof.* Let $\mathit{work}^*$ be the value of $\mathit{work}$ when the reduction stops. Then $\mathit{work}^*[r] = t(r) - \sum_{q \in L} \mathit{held}[q][r]$, because each removed process gave back all its units and Lemma 1 gives the starting value. Take $p \in L$. As $p$ is not removable, there is a type $r$ with $\mathit{req}[p][r] > \mathit{work}^*[r]$. So $\sum_{q \in L} \mathit{held}[q][r] > t(r) - \mathit{req}[p][r] \ge \mathit{held}[p][r]$, where the last step is the precondition of REQUEST. Hence some $q \in L$ with $q \ne p$ has $\mathit{held}[q][r] > 0$, and the graph has the path $p \to r \to q$, which is the wait-for edge $p \to q$ with both ends in $L$. Each vertex of the finite set $L$ has an out-edge inside $L$. Walk along these edges from any vertex; after at most $|L|$ steps a vertex repeats, and the walk between the two visits is a cycle. $\square$

**Lemma 3 (single units: a cycle is a deadlock).** If $t(r) = 1$ for every $r$ and the wait-for graph has a cycle $p_0 \to p_1 \to \cdots \to p_{k-1} \to p_0$, then every $p_i$ is deadlocked.

*Proof.* The edge $p_i \to p_{i+1}$ (indices mod $k$) means that $p_i$ requests a type $r_i$ and $p_{i+1}$ holds a unit of $r_i$. As $t(r_i) = 1$, $\mathit{avail}[r_i] = 0 < \mathit{req}[p_i][r_i]$, so $p_i$ is blocked. We show by induction on the number of steps that in every state reachable from the current one, each $p_i$ still holds $r_{i-1}$ and still requests $r_i$. This is true now. Assume it is true in a state. Every $p_i$ is blocked there, so the next step is a step of some process outside the cycle, which cannot release a unit that a $p_i$ holds and cannot change the requests of a $p_i$. So the claim holds after the step. Hence every $p_i$ is blocked in every reachable state. $\square$

**Corollary.** With single units, the state has a deadlock if and only if the wait-for graph has a cycle. One direction is Lemma 3. For the other, a deadlocked process is in $L$, and Lemma 2 gives a cycle.

**Lemma 4 (the claim edge test).** Let every type have one unit, and let $\mathit{claim}[p]$ be the set of types that $p$ may still use, with every held or requested type in $\mathit{claim}[p]$. Call the state *safe* if there is an order $p_{(1)}, \ldots, p_{(n)}$ of the processes such that each $p_{(i)}$ finds every type of $\mathit{claim}[p_{(i)}]$ that it does not hold free after $p_{(1)}, \ldots, p_{(i-1)}$ release all their units. Let $C$ be the graph with an edge $p \to r$ for each $r \in \mathit{claim}[p]$ that $p$ does not hold, and an edge $r \to q$ when $q$ holds $r$. Then the state is safe if and only if $C$ has no cycle. So SAFE-GRANT (lines L14 to L16) moves only from safe states to safe states.

*Proof.* Suppose $C$ has a cycle $p_0 \to r_0 \to p_1 \to r_1 \to \cdots \to p_0$, where $p_{i+1}$ holds $r_i$ and $p_i$ needs it. In any order, let $p_j$ be the first process of the cycle. When its turn comes, $p_{j+1}$ has not released $r_j$, so $r_j$ is not free, and the order fails. So the state is unsafe. Conversely, suppose $C$ has no cycle. Then $C$ has a topological order, and we list the processes in the reverse of that order restricted to processes: if $p \to r \to q$, then $q$ comes before $p$. When $p$ has its turn, each type $r$ that $p$ needs and does not hold is either free or held by a $q$ with $p \to r \to q$, and that $q$ came earlier and released $r$. So every $p$ finds what it needs, and the state is safe. SAFE-GRANT keeps the new assignment only if the cycle test of line L15 finds no cycle, so the new state is safe. $\square$

$\blacksquare$
