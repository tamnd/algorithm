---
title: The LZMA range decoder returns the coded bits, and the cached byte absorbs every carry
proves: [correctness, termination, length]
status: full
---

Notation. All numbers are integers. The encoder state is $(low, range, cache, cs)$ and the bytes already written. The *pending block* is the byte $cache$ followed by $cs - 1$ bytes 0xFF. We read the output bytes $B_0 B_1 B_2 \ldots$ as the real number $X = \sum_{i \ge 0} B_i \, 256^{4 - i}$, so that the first five bytes form the integer part. We measure every quantity in units of the last bit of $low$. The *value* of the state is $V = (W \cdot 256^{cs} + P) \cdot 2^{32} + low$, where $W$ is the integer of the written bytes and $P = cache \cdot 256^{cs - 1} + (256^{cs-1} - 1)$ is the integer of the pending block. The current interval is $[V, V + range)$ in these units. A SHIFT-LOW makes the unit $1/256$ of the old unit.

**Lemma 1 (bounds).** (a) Each prob stays in $[31, 2017]$. (b) Before each coded bit, $range \ge 2^{24}$, and after the bit and one shift by 8 bits, $range \ge 2^{24}$ again, so the loop of line L7 runs at most once and the `if` of line L21 is enough. (c) At each time, $low + range \le 2^{33}$. (d) If $cache = \text{0xFF}$ and $cs \ge 1$, then $low + range \le 2^{32}$.

*Proof.* (a) Line L4 adds $\lfloor (2048 - p)/32 \rfloor$, which is 0 for $p \ge 2017$, and it gives at most $p + (2048 - p)/32 \le 2017$ for $p \le 2016$, since then $(2048 - p)/32 \ge 1$ and the step leaves at least 31 to go. Line L6 is symmetric with $p \ge 31$. Both start at 1024. (b) With $range \ge 2^{24}$, $q = \lfloor range / 2^{11} \rfloor \ge 2^{13}$. A 0 bit leaves $range = q \cdot prob \ge 2^{13} \cdot 31 > 2^{16}$, and a 1 bit leaves $range - q \cdot prob \ge q (2048 - 2017) \ge 2^{13} \cdot 31$. One shift by 8 bits gives more than $2^{24}$. A direct bit halves $range$, which leaves at least $2^{23}$. (c) Line L5 and line L3 replace $[low, low + range)$ by a subinterval, so $low + range$ does not grow. After SHIFT-LOW and the shift of $range$, the new $low$ is $(low \bmod 2^{24}) \cdot 2^8 < 2^{32}$ and the new $range$ is less than $2^{32}$, so the sum is less than $2^{33}$. (d) $cache$ becomes 0xFF only at line L14 in the case $low \ge 2^{32}$ with $\lfloor low / 2^{24} \rfloor \bmod 256 = \text{0xFF}$, so $low \ge 2^{32} + \text{0xFF000000}$. By (c), $low + range_{old} \le 2^{33}$, where $range_{old} = range / 256$ is the range before the shift. After the shift, the new $low + range$ is $256 \cdot (low - 2^{32} - \text{0xFF000000} + range_{old}) \le 256 \cdot 2^{24} = 2^{32}$. Later bits do not increase $low + range$. A later SHIFT-LOW that does not write (top byte 0xFF, no carry) keeps the block and gives the new sum $256 (low - \text{0xFF000000} + range_{old}) \le 256 \cdot 2^{24}$, since $low + range_{old} \le 2^{32}$. $\square$

**Lemma 2 (the value is exact).** Let $A$ be the exact lower end of the interval of the bits coded so far, in the current units. Then $V = A$, and $[V, V + range)$ is the exact interval of the coded bits. SHIFT-LOW writes only bytes that no later bit can change.

*Proof.* By induction on the operations. At the start $V = 0 \cdot 2^{32} + 0 = 0$, $range = 2^{32} - 1$, and the first pending byte is the byte $B_0$. Lines L2 to L6 replace the interval by its lower part of width $bound$ or its upper part, and they add $bound$ to $low$, so they add $bound$ to $V$. Now take a SHIFT-LOW, and let $range_{old}$ be the range in the old units.

Case (a): $low < \text{0xFF000000}$. When line L7 calls SHIFT-LOW, $range_{old} < 2^{24}$, so $low + range_{old} < \text{0xFF000000} + 2^{24} = 2^{32}$. During FLUSH no bit follows. No later bit makes $low$ reach $2^{32}$, so no carry will enter the pending block, and line L13 writes it unchanged. The new pending byte is $t = \lfloor low / 2^{24} \rfloor \le \text{0xFE}$.

Case (b): $low \ge 2^{32}$. Then the carry $\lfloor low / 2^{32} \rfloor$ is 1, because $low < 2^{33}$ by Lemma 1(c). By Lemma 1(d), $cache \ne \text{0xFF}$, so $cache + 1 \le \text{0xFF}$, and the block plus the carry is the bytes $cache + 1, 0, \ldots, 0$. This is base-256 addition of 1 to the block, and it does not reach the written bytes. Line L13 writes it. As in case (a), the new value with the block written and the new pending byte equals the old value.

Case (c): $\text{0xFF000000} \le low < 2^{32}$. Then the top byte of $low$ is 0xFF. The block grows by one byte 0xFF, and nothing is written. The value does not change.

In all cases line L16 keeps the low 24 bits of $low$, and the new unit is $1/256$ of the old one, so $V$ is the same number in the new units. $\square$

**Lemma 3 (the output).** After FLUSH, $X$ equals the exact lower end $A$ of the final interval, in the units of the first state. So $X$ lies in every interval of the coding.

*Proof.* FLUSH calls SHIFT-LOW five times and codes no bit. The first four calls move the four bytes of $low$ into the pending block, and after them $low = 0$. So the fifth call is case (a) of Lemma 2: it writes the whole block, and the only byte left in the cache is a 0. By Lemma 2 the value did not change, so $X$ is the value $V$ in the first units, which is $A$. The intervals are nested, so $A$ lies in each of them. In the first units $A < 2^{32} - 1$, so $B_0 = 0$. $\square$

**Theorem (correctness).** For each sequence of bits and contexts, DECODE-BIT returns the bits in order, and the probabilities of the decoder equal those of the encoder at each step. Bytes past the end of the stream may be read as zeros.

*Proof.* Let $A_t$ and $range_t$ be the encoder's lower end and range before bit $t$, with $k_t$ shifts done. We show by induction on $t$ that the decoder has the same $range_t$ and the same probabilities, and that $code = \lfloor (X - A_t) \cdot 256^{k_t} \rfloor$ with $0 \le code < range_t$. At the start, line L17 reads five bytes, $code = \lfloor X \rfloor$, the first byte is 0, $A_0 = 0$, and $X < 2^{32} - 1$ because $X$ lies in the first interval. In a step, $X$ lies in the interval of bit $t$ by Lemma 3. The encoder's interval of a 0 bit is $[A_t, A_t + bound)$ in the current units, and of a 1 bit $[A_t + bound, A_t + range_t)$. Both sides compute the same $bound$ from the same $range_t$ and probability. So $code < bound$ holds exactly when the bit is 0, and lines L19 and L20 make the same changes to $range$ and to the probability as lines L3 to L6, and they keep $code = \lfloor (X - A_{t+1}) 256^{k_t} \rfloor$. A shift at line L21 happens exactly when line L7 shifts, by Lemma 1(b). Since $A_{t+1} \cdot 256^{k_t + 1}$ is an integer, the new $\lfloor (X - A_{t+1}) 256^{k_t + 1} \rfloor$ is $256 \cdot code$ plus the next base-256 digit of $X$, which is the next byte. The mask to 32 bits does not change the value, because the result is less than $range < 2^{32}$. The bytes past the written ones are zero digits of $X$. $\square$

**Theorem (length).** Let the coded bits have the model probabilities $p_1, \ldots, p_n$, where $p_j$ is $prob/2048$ for a 0 bit and $1 - prob/2048$ for a 1 bit. Then the output has at most $\sum_j \lg(1/p_j) + n \lg\bigl(1/(1 - 2^{-13})\bigr) + 40$ bits.

*Proof.* Let $w_j$ be the ratio of the new range to the old range at bit $j$, with $r$ the old range. For a 1 bit, $w_j = (r - \lfloor r/2^{11} \rfloor\, prob)/r \ge 1 - prob/2^{11} = p_j$. For a 0 bit, $w_j = \lfloor r/2^{11} \rfloor\, prob / r \ge (r/2^{11} - 1)\, prob/r = p_j (1 - 2^{11}/r) \ge p_j (1 - 2^{-13})$, since $r \ge 2^{24}$ by Lemma 1(b). A shift multiplies $range$ by 256 and makes the unit 256 times smaller, so after $k$ shifts during the coding, $range_{\text{final}} \cdot 256^{-k} = (2^{32} - 1) \prod_j w_j$. Since $range_{\text{final}} \le 2^{32} - 1$, this gives $256^k \le 1/\prod_j w_j$, so $8k \le \sum_j \lg(1/w_j)$. Each SHIFT-LOW adds 1 to $cs$, each written byte takes 1 from it, and $cs = 1$ at the start and at the end, so the number of written bytes equals the number of shifts, $k + 5$. The output has $8k + 40$ bits. $\square$

**Termination.** Each coded bit makes at most one shift (Lemma 1(b)), and FLUSH makes five calls. Line L13 runs $cs$ times, and each run writes a byte that $cs$ counted, so the total work is linear in the number of bits plus the number of output bytes. $\blacksquare$
