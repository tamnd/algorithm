---
title: Linear space and logarithmic query time for the chain method with fractional cascading
proves: [time.build, time.query, space.extra]
status: full
---

**Setting.** A regular planar straight-line graph with $n$ edges, $N$ vertices and $f$ bounded faces, and the structure of the page: a tree with the keys $1, \ldots, 2^k - 1$, where $k$ is the number of binary digits of $f + 1$, lists $L(m)$ and augmented lists $A(m)$. Costs are on the real RAM; for the trailing-zero computation of line L4 see Step 2.

**Claim.** (a) The tree has $k \le \log_2 (n + 1) + 1$ levels and fewer than $2n + 2$ nodes. (b) $\sum_m |A(m)| \le 2n$, so the structure takes $O(n)$ space in the worst case. (c) The build takes $O(n \log n)$ time in the worst case. (d) A query makes at most one orientation test and at most one step of line L9 per level, so it takes $O(\log n)$ time in the worst case; without cascading it takes $O(\log^2 n)$ time in the worst case.

**Step 1 (sizes, a).** A regular graph is connected (Proposition 1 of the [monotone subdivision](/monotone-subdivision/) page), so Euler's formula gives $N - n + (f + 1) = 2$, and $f = n - N + 1 \le n - 1$ since $N \ge 2$. So $f + 1 \le n$, and $f + 1 < 2^k \le 2(f + 1)$, which gives $2^k - 1 < 2n$ nodes and $k \le \log_2 n + 1$ levels.

**Step 2 (build time, c).** Line L1 sorts the edges at each vertex by orientation tests, in $\sum_v O(\deg v \log \deg v) = O(n \log n)$ time, and traces each of the $2n$ half-edges once with an $O(1)$ next step, using the position of each edge in the cyclic order at its end point. Line L2 is a topological sort of a graph with $f$ nodes and at most $n$ arcs, in $O(n)$ time; the heap that the code uses for its tie rule adds a factor $O(\log n)$. Line L3 is $O(1)$ per edge. In line L4, the key $m$ of an interval $[x, y]$ of keys with the most trailing zeros is the first node on the path from the root that lies in $[x, y]$: at a node outside the interval, the interval is on one side, and the search goes there. This takes $O(k) = O(\log n)$ per edge, or $O(1)$ with a word instruction for the highest differing binary digit of $x - 1$ and $y$, as in the code. Sorting the lists $L(m)$ takes $O(n \log n)$. Line L5 processes the nodes level by level from the leaves; $A(m)$ is the merge of three sorted lists, and the pointers into a child are computed by one simultaneous scan of $A(m)$ and $A(c)$, so node $m$ costs $O(|A(m)| + |A(c_1)| + |A(c_2)| + 1)$. Summed over the nodes, each list is counted at most twice, so line L5 takes $O(n + 2^k) = O(n)$ by (b) and Step 1. The total is $O(n \log n)$ in the worst case.

**Step 3 (space, b).** Each edge is stored in exactly one list $L(m)$, so $\sum_m |L(m)| = n$. Let $S = \sum_m |A(m)|$. Since $|A(m)| = |L(m)| + \lfloor |A(c_1)| / 2 \rfloor + \lfloor |A(c_2)| / 2 \rfloor$ and every node except the root is a child of exactly one node,

$$S \le \sum_m |L(m)| + \frac{1}{2} \sum_{m \ne \mathrm{root}} |A(m)| \le n + \frac{S}{2},$$

so $S \le 2n$. The arrays $\mathrm{nat}$ and $\mathrm{down}$ have $|A(m)| + 1$ entries per node and child, so the whole structure takes $O(S + 2^k) = O(n)$ space in the worst case, by Step 1. For comparison, the example of the long shared edges on the [monotone subdivision](/monotone-subdivision/) page has chains with $\Theta(n^2)$ entries in total.

**Step 4 (query time, d).** Line L6 is a binary search in $A(\mathrm{root})$, which has at most $2n$ keys, so it costs $O(\log n)$. The loop visits one node per level, $k$ nodes, and at each it does $O(1)$ work besides line L9: one lookup in $\mathrm{nat}$, one comparison with a right end point, and at most one orientation test. For line L9, let $p$ be the position given by the pointer and $p'$ the final position, the number of keys of $A(c)$ smaller than $q$ (Step 3 of [the correctness proof](../correctness/)). The keys of $A(c)$ at the positions $p, \ldots, p' - 1$ are larger than the $\mathrm{pos}$-th key $\kappa$ of $A(m)$ (or there is no such key) and smaller than $q$. A key of $A(c)$ copied into $A(m)$ with such a value would be a key of $A(m)$ strictly between $\kappa$ and $q$, which contradicts the choice of $\mathrm{pos}$ as the number of keys of $A(m)$ smaller than $q$. So none of the positions $p, \ldots, p' - 1$ is odd, since the keys at odd positions are copied. Two consecutive positions contain an odd one, so $p' - p \le 1$: the loop runs at most once. A query therefore takes $O(\log n) + k \cdot O(1) = O(\log n)$ time in the worst case. Without cascading, each node costs a binary search in $L(m)$, $O(\log n)$, and the query takes $O(k \log n) = O(\log^2 n)$ time in the worst case.

**Step 5 (tightness).** No method in the algebraic decision tree model answers point location in fewer than $\Omega(\log n)$ steps in the worst case, since a subdivision with $n$ faces has $n$ different answers and each test has at most three outcomes; see [planar point location](/planar-point-location/). So the query bound is optimal, and the space bound is optimal because the input has size $n$.
