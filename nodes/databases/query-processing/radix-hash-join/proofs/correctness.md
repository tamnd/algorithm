---
title: Radix hash join returns the bag join, with O(P(n + m)/B + (n + m + T)/B + 2^b) cache misses when the clusters fit
proves: [correctness, termination, time.average, io.average]
status: full
---

We use the line numbers of the pseudocode. We treat each stored tuple as a distinct occurrence, so $R$ and $S$ are bags and the join is the bag join: one copy of $r \cdot s$ for each pair of occurrences with $r.a = s.b$. Let $b = b_1 + \dots + b_P$, let $c(x) = h(x.\mathit{key}) \bmod 2^b$ be the *cluster number* of a tuple, and let $s_p = b - (b_1 + \dots + b_p)$ be the shift of line L3 in pass $p$, with $s_0 = b$.

**Lemma 1 (one pass).** Before pass $p$, assume that $X$ is a permutation of the input and that it is cut into contiguous clusters, one for each value $v < 2^{b - s_{p-1}}$, in increasing order of $v$, where the cluster of $v$ holds the tuples with $c(x) \gg s_{p-1} = v$ in input order. Then after pass $p$, the same holds with $s_p$ in place of $s_{p-1}$.

*Proof.* Take one cluster $C$ with value $v$ (line L4). Its tuples have $c(x) \gg s_p = v \cdot 2^{b_p} + j$, where $j = (h(x.\mathit{key}) \gg s_p) \bmod 2^{b_p}$ is the digit of line L5. Line L5 counts the tuples with each digit $j$. Line L6 sets $\mathit{start}[j]$ to the start of $C$ plus the number of tuples of $C$ with a smaller digit, so the ranges $[\mathit{start}[j], \mathit{start}[j] + \mathit{count}[j])$ for $j = 0, \dots, 2^{b_p} - 1$ cut the range of $C$ into consecutive pieces in increasing order of $j$. Line L7 visits $C$ in order and writes each tuple with digit $j$ to the next free place of piece $j$. So piece $j$ receives exactly the tuples of $C$ with digit $j$, in input order, and every place of the range of $C$ is written once. The pieces of $C$ have the values $v \cdot 2^{b_p} + j$, which are increasing in $j$ and lie between the values of the pieces of the clusters before and after $C$. Line L8 keeps this order. $\square$

**Lemma 2 (clustering).** RADIX-CLUSTER returns a permutation of its input in which cluster $i$, the range from $\mathit{bounds}[i]$ to $\mathit{bounds}[i+1]$, holds exactly the tuples $x$ with $c(x) = i$, in input order.

*Proof.* Before pass 1, $s_0 = b$, so $c(x) \gg b = 0$ for every tuple, and the whole input is the single cluster of value 0. This is the hypothesis of Lemma 1 for $p = 1$. By induction with Lemma 1, after pass $P$ the claim holds with $s_P = 0$, that is, with $c(x)$ itself. $\square$

**Theorem 1 (correctness).** RADIX-JOIN returns a list whose multiset of elements is $R \bowtie S$ (bag semantics, a NULL key never matches).

*Proof.* A pair $(r, s)$ with $r.a = s.b$ has $h(r.a) = h(s.b)$, so $c(r) = c(s)$, and by Lemma 2 $r$ is in cluster $i = c(r)$ of $R$ and $s$ in cluster $i$ of $S$. So every matching pair lies in one pair of clusters with the same number, and in no other. Line L12 inserts each occurrence of cluster $i$ of $R$ once into a chained table: it prepends it to the chain of its bucket and never removes it. Line L13 meets each occurrence $s$ of cluster $i$ of $S$ once, walks the whole chain of the bucket of $s.b$, which holds every occurrence of $R_i$ with key $s.b$ (equal keys have equal hash and so equal bucket), and appends $r \cdot s$ exactly when $r.a = s.b$. So each matching pair gives exactly one output, and nothing else is appended. All loops run over finite ranges, so the algorithm stops. $\blacksquare$

**Theorem 2 (work).** In the word RAM, RADIX-CLUSTER does $O(P n + 2^b)$ steps on $n$ tuples. Under the simple uniform hashing assumption for the bucket bits (the bits of $h$ above the low $b$ bits), the expected work of RADIX-JOIN is $O(P(n + m) + 2^b + T)$. Its worst case is $O(P(n + m) + 2^b + n m)$.

*Proof.* Pass $p$ handles each tuple twice (lines L5 and L7) and does $O(2^{b_p})$ work per cluster for lines L5 and L6. Before pass $p$ there are $2^{b_1 + \dots + b_{p-1}}$ clusters, so the counters cost $\sum_p 2^{b_1 + \dots + b_p} \le 2 \cdot 2^b$ in total. This gives $O(P n + 2^b)$. In the join phase, cluster $i$ gets a table with at least $|R_i|$ buckets. A probe compares $s.b$ with the tuples of $R_i$ in its bucket: those with key $s.b$ each give an output, and under the assumption each other key of $R_i$ lands in the bucket with probability at most $1/|R_i|$, so the expected number of the other comparisons is at most 1 per probe. Summing over clusters gives $O(n + m + T + 2^b)$. In the worst case every probe walks a whole cluster, at most $n m$ comparisons in total. $\blacksquare$

**The cache model.** We use the [external memory model](/external-memory-model/) for the cache: the cache holds $M$ words in $M/B$ lines of $B$ words, a miss moves one line, and we may choose which lines to keep (an optimal replacement). In the external memory model, the memory holds $M/B$ blocks; on this page the memory is the cache and a block is a cache line, so the cache holds $M/B$ lines. Each tuple takes one word.

**Theorem 3 (cache misses).** Assume that every pass has a fan-out $F_p = 2^{b_p}$ with $F_p (1 + 1/B) + 3 \le M/B$, and that every cluster of $R$ satisfies $4|R_i| + 3B \le M$. Then RADIX-JOIN has $O(P(n + m)/B + (n + m + T)/B + 2^b)$ cache misses.

*Proof.* Take one cluster $C$ of size $|C|$ in pass $p$. Line L5 reads $C$ in order and updates $F_p$ counters that fill $F_p / B + 1$ lines: keep these lines and one input line, which costs $|C|/B + F_p/B + 3$ misses. Line L7 reads $C$ again in order and writes to $F_p$ output places, each of which moves forward one word at a time. Keep one line for the input, one line for each of the $F_p$ output cursors and the lines of the counters. By the assumption these fit. Each output cursor misses once at its start and once per $B$ words, so the writes cost at most $|C|/B + 2 F_p$ misses, and the reads $|C|/B + 2$. Summed over the clusters of pass $p$, this is $O(n/B + 2^{b_1 + \dots + b_p})$, and over all passes $O(P n / B + 2^b)$. The same holds for $S$.

In the join phase, cluster $i$ needs its $|R_i|$ tuples, its head array of fewer than $2|R_i|$ words and its next array of $|R_i|$ words, at most $4|R_i|$ words, plus one line for $S_i$ and one line for the output. By the assumption they fit, so line L12 costs $O(|R_i|/B + 1)$ misses, and line L13 then misses only on the lines of $S_i$ and of the output: $O((|S_i| + T_i)/B + 1)$, where $T_i$ is the output of the cluster. The sum over the $2^b$ clusters is $O((n + m + T)/B + 2^b)$. $\blacksquare$

The second assumption depends on the data. With $b$ radix bits and no heavy key, the clusters of $R$ have about $n / 2^b$ tuples, so $b$ is chosen near $\log_2 (4 n / M)$. A key that occurs more than $M/4$ times makes a cluster that does not fit, whatever $b$ is.

**Without partitioning.** Let the plain hash join build one table of $W > M$ words on all of $R$, and let the probe keys be such that the bucket of each probe is uniform over the buckets and independent of the cache contents. At a probe, at most $M$ words of the table are in the cache, so the probe misses with probability at least $1 - M/W$. So the expected number of misses is at least $m(1 - M/W)$, which is close to one miss per probe when $W \gg M$, against $O(1/B)$ per tuple for the radix join under the assumptions of Theorem 3.

**Real caches.** A hardware cache uses a fixed replacement rule such as LRU and is set associative, not the optimal replacement of the model. By the resource augmentation result for [LRU](/lru/) of Sleator and Tarjan, LRU with twice the lines has at most about twice the misses of the optimal rule, so Theorem 3 holds for LRU with the fan-out and cluster limits halved. The translation lookaside buffer (TLB) is a small cache of page translations, and the same counting with a page in place of a line and the number of TLB entries in place of $M/B$ shows why the fan-out $F_p$ of one pass must stay below the number of TLB entries.
