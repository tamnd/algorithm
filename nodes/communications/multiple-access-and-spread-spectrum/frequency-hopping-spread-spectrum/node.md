Frequency-hopping spread spectrum (FHSS) sends a narrowband signal, usually [frequency-shift keying](/frequency-shift-keying/), on a carrier that jumps from channel to channel by a pseudorandom pattern. The transmitter and the receiver step through the same pattern in time, so the receiver always listens on the right channel. At any instant the signal is narrow, but over many hops it covers a band about $q$ channels wide. An interferer on one channel, or another user with a different pattern, hits only the hops that land on its channel. An error-correcting code with [interleaving](/interleaving/) across hops then repairs those few hops. The [processing gain](/processing-gain/) is about the number of channels $q$. Bluetooth Classic uses FHSS with $79$ channels and $1600$ hops per second.

## In plain words

The sender and the receiver agree on a long list of channels that looks random. They talk on the first channel for a short time, then both move to the next channel on the list, and so on.

Someone who blocks one channel spoils only the short pieces that fall on that channel, which is a small part of the message. The message carries some extra check data, and the pieces are mixed in time, so the receiver can rebuild the spoiled parts.

Many pairs can share the band, each with its own list. Two pairs disturb each other only when their lists name the same channel at the same time, which does not happen often.

The hard part is to keep both ends in step: they must agree on where they are in the list and when each hop starts.

## When it applies

- The band contains strong narrowband interference, or a jammer that can cover only part of the band at a time.
- The signal cannot easily be made very wide at once, for example because the hardware is narrowband, but a synthesizer can retune quickly.
- Several uncoordinated systems share an unlicensed band, and each must survive the others.
- Noncoherent detection is acceptable. Keeping the carrier phase across hops is hard, so FHSS usually uses FSK with [noncoherent detection](/noncoherent-detection/).
- A code is used across hops, because a jammed hop is often lost as a whole.

## The template

Let there be $q$ channels at the frequencies $f_0, \ldots, f_{q-1}$, a hop duration $T_h$, and a pseudorandom hop sequence $a_0, a_1, \ldots$ with values in $\{0, \ldots, q - 1\}$, generated by a key that both ends share. In hop $i$, the transmitter sends its symbols on the channel $f_{a_i}$; the receiver mixes the input down by $f_{a_i}$ and demodulates.

```pseudo id=main
FH-SEND(symbols, key)
L1  a ← hop sequence from key
L2  encode and interleave the data, so that each codeword is spread over many hops
L3  for each hop i do
L4      send the symbols of hop i on the channel f_{a_i}

FH-RECEIVE(r, key)
L5  for each hop i do demodulate r on the channel f_{a_i}, and mark the hop as an erasure if it looks jammed
L6  de-interleave and decode, with erasures
```

**Slow and fast hopping.** In **slow hopping**, each hop carries several symbols. In **fast hopping**, each symbol is spread over several hops, and the receiver combines the hops of one symbol. Fast hopping gives diversity within a symbol, but it needs a faster synthesizer and loses more energy in the switching time.

**Collisions.** If $K$ users hop independently and uniformly over $q$ channels, a given hop of one user collides with at least one other user with probability $1 - (1 - 1/q)^{K-1}$. This assumes hops that are aligned in time; unaligned hops collide more often.

## Classic examples

- **Bluetooth Classic.** It uses $79$ channels of $1$ MHz in the 2.4 GHz band and $1600$ hops per second, so a hop lasts $625$ microseconds. If $K$ independent links hop over the $79$ channels, a given hop collides with probability $0.0127$ for $K = 2$, $0.0497$ for $K = 5$, $0.108$ for $K = 10$ and $0.215$ for $K = 20$. Adaptive frequency hopping removes the channels that are found to be busy, for example those used by a Wi-Fi network.
- **Partial-band jamming with a code.** Suppose a jammer covers a fraction $\rho = 0.1$ of the channels, so each hop is jammed with probability $0.1$, independently. A code that can repair up to $2$ lost hops in a block of $15$ fails with probability $0.184$ per block. A stronger code that repairs more erasures lowers this quickly, since the number of jammed hops follows a binomial law.
- **The Markey-Antheil patent.** The actress Hedy Lamarr, under her married name Hedy Kiesler Markey, and the composer George Antheil patented in 1942 a secret radio control system in which the transmitter and the receiver changed frequency in step, kept together by matching mechanisms at the two ends.
- **Military radios.** Tactical radios use fast or slow hopping over wide bands for resistance to jamming and interception.

## Variations

- **Adaptive hopping.** The hop set changes with the measured channel quality, as in Bluetooth adaptive frequency hopping.
- **Hop patterns with low coincidence.** A [Costas array](/costas-array/) gives a pattern whose shifts in time and frequency coincide in at most one hop, which is useful for radar and for hop patterns of several users.
- **Hybrid DS/FH.** Each hop carries a [direct-sequence](/direct-sequence-spread-spectrum/) signal, which combines the processing gains.
- **Orthogonal hopping.** In a synchronized network, the users of one cell hop with patterns that never use the same channel at the same time. Then collisions inside the cell do not occur, and only users of other cells collide.
- **Time hopping.** The pulse position, not the frequency, follows the pseudorandom pattern.

## Pitfalls

- **No gain against white noise.** As for all spreading, hopping does not change $E_b/N_0$ on an AWGN channel.
- **Uncoded hopping does not work well against jamming.** A jammed hop gives a burst of errors. Without a code and interleaving across hops, a partial-band jammer still sets a floor on the error rate of about $\rho$ times the error rate in a jammed hop.
- **Synchronization.** Both ends must know the time of each hop and the position in the pattern. A receiver that joins late must search over both, which takes time.
- **Switching time.** The synthesizer needs time to settle after each hop. This guard time is lost, and the loss grows with the hop rate.
- **Coherent detection is hard.** The phase usually changes from hop to hop, so coherent detection needs a new phase estimate in every hop.
- **Predictable patterns.** A pattern from a short linear generator, such as a plain [m-sequence](/maximal-length-sequence/), can be predicted from a few observed hops. A pattern for resistance to an intelligent jammer must come from a cryptographic generator.
